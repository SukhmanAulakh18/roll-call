# What Roll Call contains, and what it does not

This page states the guarantee boundary in plain English, then shows the measured results. The agent used for the external tests is a Refund Processing Agent that runs as its own OS process (`examples/refund-agent/`), talks to Roll Call only through the SDK (`sdk/rollcall.ts`), and uses sandbox tools (`refunds.issue`, `tickets.read`) in which no money moves. Pager and owner acknowledgement are simulated.

## The boundary

**Guaranteed (and tested):**
- After a gateway has observed an agent's revocation, no new protected action goes through that gateway. Every later request is denied with `REVOKED`, including replays of the old token. Asking for a new identity is refused.
- Tools only serve calls that carry a fresh HMAC signature from a gateway (`x-rollcall-sig`, secret `ROLLCALL_TOOL_SECRET`). A direct call to a tool, with no signature, a forged one, a tampered body or an old capture, gets `401`.
- Refund arguments are checked by the gateway before the tool is reached. Over the limit gives `OVER_LIMIT`; strings, negatives, zero, fractions of a cent, containers and missing fields give `INVALID_ARGS`. The limit comes from the agent record (`argLimits`), default 500 CAD.

**Not guaranteed (and measured or stated):**
- An action that is already past the gateway when the kill lands completes. The gateway cannot recall it. The in-flight test reports how often this happened.
- Requests sent between the revocation and the moment a gateway observes it (up to its bundle poll interval, 200 ms here) are allowed. The concurrency test counts them.
- Any path that does not use the gateway. Tools check signatures, but whoever holds the tool secret, or a tool that does not check, is outside the guarantee. The `/v1/direct` endpoint is an ungoverned baseline for benchmarks only; it is off unless `RC_DIRECT_BASELINE=1` (or `directEnabled`) is set, and the containment tests run with it off.
- Stopping the OS process. Roll Call revokes identity. The process keeps running and keeps being denied.
- Registering a new agent id. Registration (`POST /v1/agents`) is unauthenticated in this prototype, so a process that can reach control can register a new id. A real deployment needs an owner-approved admission workflow.
- Many small in-limit refunds on one ticket. There is no cumulative per-ticket cap; the repeat detector and budgets are the only brakes.
- Everything here is one machine, one process group, loopback HTTP, no TLS, small sample sizes (n is in each row).

### Guarantee list

- **Guaranteed**: Once a gateway has observed a revocation, no new protected action goes through that gateway: every later request is denied (REVOKED). Tests: concurrency, token-replay, restart.
- **Guaranteed**: Sandbox tools reject any call that does not carry a fresh gateway HMAC signature (401), so there is no unsigned path around the gateway. Test: bypass.
- **Guaranteed**: Over-limit and malformed refund arguments are denied before the tool is reached (OVER_LIMIT, INVALID_ARGS). Test: arg-tampering.
- **Not guaranteed**: Actions already past the gateway when the kill lands. They complete. Test: in-flight.
- **Not guaranteed**: Requests sent inside the propagation window (up to the gateway bundle poll interval, 200 ms here) before a gateway has observed the revocation. They are counted in concurrency.
- **Not guaranteed**: Actions through paths that do not use the gateway: anyone holding the tool secret, or a tool that does not check signatures, is outside this guarantee.
- **Not guaranteed**: Stopping the OS process. Roll Call revokes identity; the process keeps running and keeps being denied.
- **Not guaranteed**: Registering a brand-new agent id. Registration is unauthenticated in this prototype (see restart finding).
- **Not guaranteed**: Many separate in-limit refunds on one ticket: no cumulative per-ticket cap.

## Reproduce

```
make external-demo   # starts the stack, spawns examples/refund-agent as a separate process
make containment     # seven tests, writes impact.json containment
make exec-pack       # regenerates the table above and the verification matrix
```

Failures are recorded in impact.json and shown above as FAIL; nothing is filtered out.
